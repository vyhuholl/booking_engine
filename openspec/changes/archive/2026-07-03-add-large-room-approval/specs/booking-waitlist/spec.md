## MODIFIED Requirements

### Requirement: Постановка в очередь на занятый интервал
Система SHALL позволять аутентифицированному пользователю встать в лист ожидания на интервал
комнаты запросом `POST /rooms/{id}/waitlist` с телом `{ "start_time", "end_time" }`.
Waitlist-запись MUST создаваться **только если** комната занята — то есть существует бронь в
статусе `confirmed`, `pending_approval` **или** `approved`, пересекающая запрошенный интервал.
Брони на согласовании (`pending_approval`) и одобренные (`approved`) удерживают слот наравне с
`confirmed`, поэтому встать в очередь можно и на такой слот. Если комната свободна в этом
интервале (нет удерживающей слот брони), система MUST отказать и указать, что нужно оформить
обычную бронь. Интервал MUST проходить те же проверки, что и обычная бронь:
`end_time > start_time`, `start_time` в будущем, длительность в диапазоне
`[15 минут, 8 часов]`. Комната MUST существовать и не быть `out_of_service`.

#### Scenario: Успешная постановка в очередь на занятый интервал
- **WHEN** комната занята подтверждённой бронью в интервале `[10:00, 11:00)` и member выполняет `POST /rooms/{id}/waitlist` с `start_time=10:00`, `end_time=11:00`
- **THEN** система возвращает HTTP 201 с waitlist-записью в статусе `waiting`
- **AND** запись содержит поля `id`, `room_id`, `user_id`, `start_time`, `end_time`, `position`, `status`
- **AND** `position` назначен автоматически (следующий свободный номер в очереди комнаты)

#### Scenario: Постановка в очередь на слот с pending_approval бронью
- **WHEN** интервал `[10:00, 11:00)` удерживается бронью в статусе `pending_approval` и member выполняет `POST /rooms/{id}/waitlist` на этот интервал
- **THEN** система возвращает HTTP 201 с waitlist-записью в статусе `waiting`

#### Scenario: Отказ, если комната свободна в интервале
- **WHEN** в запрошенном интервале нет брони, удерживающей слот (`confirmed`/`pending_approval`/`approved`)
- **THEN** система возвращает HTTP 409 с кодом `WAITLIST_ROOM_AVAILABLE`
- **AND** waitlist-запись не создаётся

#### Scenario: Отказ при невалидном интервале
- **WHEN** пользователь передаёт `end_time <= start_time`, либо `start_time` в прошлом, либо длительность вне диапазона `[15 минут, 8 часов]`
- **THEN** система возвращает HTTP 400 с соответствующим кодом валидации (`INVALID_TIME_RANGE` / `START_IN_PAST` / `BOOKING_DURATION_TOO_SHORT` / `BOOKING_DURATION_TOO_LONG`)

#### Scenario: Отказ для несуществующей комнаты
- **WHEN** пользователь ставит в очередь на несуществующую комнату
- **THEN** система возвращает HTTP 404 с кодом `ROOM_NOT_FOUND`

#### Scenario: Отказ для комнаты вне обслуживания
- **WHEN** комната имеет статус `out_of_service`
- **THEN** система возвращает HTTP 409 с кодом `ROOM_OUT_OF_SERVICE`

#### Scenario: Требование аутентификации
- **WHEN** запрос выполнен без валидного JWT
- **THEN** система возвращает HTTP 401
