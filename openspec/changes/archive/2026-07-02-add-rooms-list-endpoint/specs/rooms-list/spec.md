# Spec: Rooms List

Спецификация возможности получения списка комнат с фильтрацией.

## ADDED Requirements

### Requirement: Получение списка всех активных комнат
Система MUST возвращать JSON-массив всех активных комнат при запросе `GET /rooms` без параметров фильтрации. Комнаты MUST быть отсортированы по полю `name` в алфавитном порядке (ASC). В ответ MUST включаться только комнаты со статусом `active`.

#### Scenario: Успешное получение списка всех комнат
- **WHEN** аутентифицированный пользователь (любой роли) выполняет запрос `GET /rooms` без query-параметров
- **THEN** система возвращает HTTP 200 с JSON-массивом всех активных комнат
- **AND** массив отсортирован по `name` в алфавитном порядке
- **AND** каждая комната содержит поля: `id`, `name`, `floor`, `capacity`, `status`, `equipment`, `created_at`

#### Scenario: Исключение неактивных комнат
- **WHEN** в системе существуют комнаты со статусом `inactive` или `deleted`
- **THEN** ответ `GET /rooms` не содержит эти комнаты

#### Scenario: Пустой список при отсутствии активных комнат
- **WHEN** в системе нет активных комнат
- **THEN** система возвращает HTTP 200 с пустым JSON-массивом `[]`

### Requirement: Фильтрация по этажу
Система SHALL поддерживать query-параметр `floor` (integer) для фильтрации комнат по этажу. При указании параметра MUST возвращаться только комнаты, у которых поле `floor` равно указанному значению.

#### Scenario: Успешная фильтрация по этажу
- **WHEN** аутентифицированный пользователь выполняет запрос `GET /rooms?floor=3`
- **THEN** система возвращает HTTP 200 с JSON-массивом активных комнат на 3-м этаже
- **AND** результат отсортирован по `name`

#### Scenario: Пустой результат при фильтрации по несуществующему этажу
- **WHEN** аутентифицированный пользователь выполняет запрос `GET /rooms?floor=99`
- **AND** на этаже 99 нет активных комнат
- **THEN** система возвращает HTTP 200 с пустым JSON-массивом `[]`

### Requirement: Фильтрация по минимальной вместимости
Система SHALL поддерживать query-параметр `min_capacity` (integer) для фильтрации комнат по вместимости. При указании параметра MUST возвращаться только комнаты, у которых поле `capacity` больше или равно указанному значению (>=).

#### Scenario: Успешная фильтрация по вместимости
- **WHEN** аутентифицированный пользователь выполняет запрос `GET /rooms?min_capacity=10`
- **THEN** система возвращает HTTP 200 с JSON-массивом активных комнат с вместимостью >= 10
- **AND** результат отсортирован по `name`

#### Scenario: Пустой результат при фильтрации по превышающей вместимости
- **WHEN** аутентифицированный пользователь выполняет запрос `GET /rooms?min_capacity=999`
- **AND** ни одна комната не имеет такой вместимости
- **THEN** система возвращает HTTP 200 с пустым JSON-массивом `[]`

### Requirement: Комбинированная фильтрация
Система SHALL поддерживать одновременное использование обоих параметров фильтрации (`floor` и `min_capacity`). При указании обоих параметров MUST возвращаться только комнаты, удовлетворяющие обоим условиям (логическое И).

#### Scenario: Успешная комбинированная фильтрация
- **WHEN** аутентифицированный пользователь выполняет запрос `GET /rooms?floor=2&min_capacity=8`
- **THEN** система возвращает HTTP 200 с JSON-массивом активных комнат на 2-м этаже с вместимостью >= 8
- **AND** результат отсортирован по `name`

### Requirement: Валидация query-параметров
Система SHALL валидировать типы query-параметров. При передаче невалидного значения MUST возвращаться HTTP 400 с описанием ошибки.

#### Scenario: Неверный тип параметра floor
- **WHEN** аутентифицированный пользователь выполняет запрос `GET /rooms?floor=abc`
- **THEN** система возвращает HTTP 400 с описанием ошибки валидации

#### Scenario: Неверный тип параметра min_capacity
- **WHEN** аутентифицированный пользователь выполняет запрос `GET /rooms?min_capacity=xyz`
- **THEN** система возвращает HTTP 400 с описанием ошибки валидации

#### Scenario: Отрицательные значения допустимы
- **WHEN** аутентифицированный пользователь выполняет запрос `GET /rooms?floor=-1&min_capacity=-5`
- **THEN** система обрабатывает запрос как валидный (возвращает пустой массив, так как нет комнат с отрицательными значениями)

### Requirement: Требование аутентификации
Доступ к эндпоинту `GET /rooms` SHALL требовать валидный JWT-токен. Неаутентифицированные запросы MUST возвращаться с HTTP 401.

#### Scenario: Отказ при отсутствии токена
- **WHEN** неаутентифицированный пользователь выполняет запрос `GET /rooms` без заголовка Authorization
- **THEN** система возвращает HTTP 401

#### Scenario: Отказ при невалидном токене
- **WHEN** пользователь выполняет запрос `GET /rooms` с просроченным или невалидным JWT-токеном
- **THEN** система возвращает HTTP 401

### Requirement: Ролевой доступ
Эндпоинт `GET /rooms` SHALL быть доступен всем аутентифицированным ролям: `admin`, `manager`, `member`. Никаких дополнительных проверок ролей не требуется.

#### Scenario: Доступ для member
- **WHEN** аутентифицированный пользователь с ролью `member` выполняет запрос `GET /rooms`
- **THEN** система возвращает HTTP 200 со списком комнат

#### Scenario: Доступ для manager
- **WHEN** аутентифицированный пользователь с ролью `manager` выполняет запрос `GET /rooms`
- **THEN** система возвращает HTTP 200 со списком комнат

#### Scenario: Доступ для admin
- **WHEN** аутентифицированный пользователь с ролью `admin` выполняет запрос `GET /rooms`
- **THEN** система возвращает HTTP 200 со списком комнат
