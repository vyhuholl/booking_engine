# Proposal: Add Rooms List Endpoint

## Why

Текущее API не предоставляет способа получить список всех комнат с возможностью фильтрации. Клиентским приложениям (web/mobile) необходимо отображать список комнат с возможностью фильтрации по этажу и вместимости для удобства пользователей при выборе переговорной.

## What Changes

Добавить новый HTTP-endpoint `GET /rooms` со следующими возможностями:

- **Query-параметры:**
  - `floor` (int, optional) — фильтр по этажу
  - `min_capacity` (int, optional) — минимальная вместимость (включая это значение)
- **Ответ:** JSON-массив объектов комнат, отсортированных по имени (`name`) в алфавитном порядке
- **Пагинация:** не требуется (предполагается небольшое количество комнат)
- **Статус комнаты:** включать в ответ только активные комнаты (`status = "active"`)

## Capabilities

### New Capabilities

- `rooms-list`: Получение списка комнат с опциональной фильтрацией по этажу и минимальной вместимости. Результат отсортирован по имени.

### Modified Capabilities

Нет. Изменения не затрагивают существующие спецификации.

## Impact

- **Handler:** Новый хендлер `listRooms` в `internal/handler/room.go`
- **Service:** Новый метод `ListRooms` в `internal/service/room.go` с фильтрацией
- **Repository:** Новый метод `List` в `internal/repository/room.go` с SQL-фильтрами
- **Routing:** Новый маршрут в `cmd/server/router.go`
- **Auth:** Доступ для всех аутентифицированных пользователей (admin/manager/member)
- **Tests:**
  - Unit-тесты для service-слоя (валидация параметров, фильтрация)
  - Интеграционные тесты для repository (SQL-запросы)
  - HTTP-тесты для handler
